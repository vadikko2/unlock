# unlock

Инфраструктура для личного VPN (AmneziaWG) и HTTP-прокси для Cursor (GOST). Сам VDS может быть у 62yun или у Timeweb. DNS домена всегда в Timeweb.

Все сервисы крутятся в Docker Compose. Единый источник правды для клиентов — файл в репозитории (`amnezia/wireguard/wg0.json`), поэтому конфигурации не потеряются при пересоздании сервера. Деплой происходит автоматически по пушу в ветку `master`.

---

## Как это устроено

Стек описан в `docker-compose.yml` и запускается на сервере в `/opt/unlock`:

1. **`amnezia-wg-easy`** — WireGuard с обфускацией Amnezia (UDP `443`) и веб-интерфейсом (TCP `51822`). Монтирует папку `./amnezia/wireguard`, где лежит `wg0.json`.
2. **`cursor-proxy`** — легковесный GOST-прокси (TCP `1080`) с базовой авторизацией для работы Cursor без разрывов стриминга.

Репозиторий **строго приватный**, так как `wg0.json` содержит приватные ключи клиентов.

Сейчас это 62yun в Дронтене, `199.246.126.45`, панель `svr_194815`. Старый Timeweb `179.252.208.227` не получает деплой, пока `DEPLOY_HOST` указывает на 62yun.

---

## Настройка с нуля

1. **Сервер:** чистый Ubuntu VDS. Поставить Docker и Compose, положить в `/root/.ssh/authorized_keys` свой ключ и ключ из `.deploy-keys/gha_deploy.pub`. На 62yun пароль root один раз берётся из панели, дальше вход по ключу. Интерфейс там `ens192`, не `eth0`.
2. **DNS:** A-запись `24testreservation.ru` в Timeweb смотрит на IPv4 этого сервера (TTL `300`, без прокси Cloudflare). Хостер VDS и хостер DNS могут быть разными.
3. **GitHub Secrets & Variables:**
   - **Secrets** (нельзя прочитать обратно):
     - `DEPLOY_HOST` — IP сервера;
     - `DEPLOY_USER` — пользователь (`root`);
     - `DEPLOY_SSH_KEY` — приватный SSH-ключ для деплоя.
   - **Variables** (видны в настройках репозитория):
     - `WG_HOST` — домен (`24testreservation.ru`);
     - `AMNEZIA_PASSWORD` — пароль веб-панели;
     - `PROXY_USER` / `PROXY_PASSWORD` — логин и пароль прокси Cursor;
     - `PROXY_PORT` (`1080`), `WG_PORT` (`443`), `AMNEZIA_UI_PORT` (`51822`), `AMNEZIA_LANGUAGE` (`ru`).
4. **Запуск:** пуш в `master` автоматически генерирует `.env` из переменных и секретов GitHub, копирует файлы на сервер и поднимает контейнеры. Локально для тестов можно использовать `cp .env.example .env && docker compose up -d`.

## Клиент VPN

Пир пишется в `amnezia/wireguard/wg0.json` и попадает на сервер только после пуша в `master`. Пока Deploy не зелёный, новый туннель не поднимется. Через веб-панель клиентов не создавать. `clients/` в git не класть.

```bash
make add-client NAME="Phone"
git add amnezia/wireguard/wg0.json && git commit -m "feat: add client Phone" && git push
make list-clients
make export-client NAME="Phone"   # заново собрать clients/Phone.conf
```

Отдать конфиг на телефон и дальше переслать:

```bash
brew install qrcp          # один раз, программа которая показывает QR на скачивание
make send NAME="Phone"     # телефон в той же Wi‑Fi, сканировать QR в терминале
```

Скачается `Phone.conf`. Его пересылаешь кому нужно, в Amnezia — импорт файла. Остановка сервера: Ctrl+C. Если QR ведёт не в ту сеть: `make send NAME="Phone" IFACE=en1`.

Файл также лежит локально в `clients/Phone.conf`, его можно отдать AirDrop или мессенджером без QR.

## Подключение Cursor через прокси

В настройках Cursor (`Cmd + Shift + P` -> `Preferences: Open User Settings (JSON)`):

```json
"http.proxy": "http://PROXY_USER:PROXY_PASSWORD@24testreservation.ru:1080",
"http.proxyStrictSSL": true,
"http.proxySupport": "override",
"cursor.general.disableHttp2": true
```

- В адресе прокси всегда домен `24testreservation.ru`, не IP. После смены IP A-запись обновляется, строка в Cursor остаётся той же.
- Параметр `cursor.general.disableHttp2: true` критичен: без него стриминг ответов ИИ виснет.
- После сохранения полностью перезапустите Cursor.

## Смена IP или переезд на другой VDS

`WG_HOST` и строка прокси в Cursor всегда остаются доменом. Меняется A-запись в Timeweb и секрет `DEPLOY_HOST`.

Новый адрес сначала должен отвечать с дома, и только потом его можно ставить в DNS. Проверять надо, пока адрес ещё висит на интерфейсе. Трассировка до уже снятого IP ничего не доказывает.

С этой домашней сети путь такой: роутер `192.168.0.1`, затем `10.150.162.1` и `10.148.252.13`. Если трассировка обрывается здесь, провайдер Wi-Fi не выпускает эту подсеть. Так было с несколькими адресами Timeweb в Амстердаме. Мобильный оператор может резать другую подсеть, чем домашний Wi-Fi. Пинг сам по себе мало что значит: у 62yun ICMP молчит, а TCP `1080`, `51822` и UDP `443` при этом проходят.

Порядок:

1. Поставить адрес на машину. На 62yun это кнопка «Заменить IP» в панели или новый сервер с уже выданным IPv4. На Timeweb это плавающий IP в той же зоне, и его ещё надо прописать на `eth0` как `/32`: сама привязка и ребут адрес не добавляют.
2. С дома, не через туннель: трассировка уходит дальше `10.148.252.13`, порты `1080` и `51822` открываются, а UDP-пакет на `443` виден в `tcpdump` на сервере.
3. Обновить A-запись в Timeweb (TTL `300`) и секрет `DEPLOY_HOST`, если деплой ещё смотрит на старый IP. Запустить Deploy to VDS и дождаться зелёного прогона. Пиры в `wg show` не должны обнулиться.
4. `dig +short 24testreservation.ru` должен показать новый IP. Серверы имён Timeweb могут отставать на несколько минут после того, как панель уже сохранила запись. Локальный кэш держит старый ответ до конца TTL.
5. Выключить и включить туннель Amnezia. Ключи заново не выпускать. Cursor полностью закрыть через Cmd+Q: старые соединения к прошлому IP сами не отваливаются.

Скилл `/change-ip` делает этот чек-лист сам и различает 62yun и Timeweb.

## Как чинить (Troubleshooting)

### VPN не подключается
1. Проверьте контейнеры на сервере:
   ```bash
   docker compose -f /opt/unlock/docker-compose.yml ps
   ```
2. Убедитесь, что WireGuard активен и видит пиров:
   ```bash
   docker exec amnezia-wg-easy wg show
   ```
3. С дома, не через туннель, проверьте TCP `1080` и что UDP `443` доходит до сервера (`tcpdump` на `ens192` у 62yun или на `eth0` у Timeweb). Обрыв трассировки на `10.148.252.13` значит, что эту подсеть не выпускает домашний провайдер. Молчащий пинг при живых портах — норма для 62yun, это не повод менять IP.

### Cursor не работает через прокси
1. Посмотрите логи прокси в реальном времени:
   ```bash
   docker logs -f cursor-proxy
   ```
   При запросах должны появляться строки вида `[http] ... <-> api2.cursor.sh:443`.
2. Проверьте доступность с самого сервера:
   ```bash
   curl -sS -x http://USER:PASSWORD@127.0.0.1:1080 https://api.ipify.org
   ```
3. Если запросы висят — убедитесь, что в Cursor выключен HTTP/2 (`cursor.general.disableHttp2: true`) и редактор был перезапущен.

### Рассинхрон или сбой конфигурации
Так как всё хранится в git, сервер всегда можно вернуть в рабочее состояние:
```bash
cd /opt/unlock
docker compose down
docker compose up -d --build
```
`amnezia-wg-easy` заново пересоберет рабочий `wg0.conf` из подмонтированного `amnezia/wireguard/wg0.json`.
